# Quintによる形式検証

状態やイベントの順序によって動作が変わる箇所を、Quintの実行可能な仕様として管理する。TLCは各モデルの初期状態から到達できる有限状態を探索し、不変条件 `safety` に違反すると、そこに至る操作列を出力する。

## 実行

Node.jsとnpm、JDK 21、PowerShell 7を用意する。Rustの照合テストには通常のビルド環境と、推論クレートが埋め込む3個のMediaPipeモデルが必要になる。[ソースからのビルド](../tools/BUILDING.md)

リポジトリのルートで実行する。

```powershell
./tools/verify-quint.ps1
```

スクリプトはQuint 0.34.0を起動し、各モデルをTLCで検査する。続いて、シナリオテストと固定シードのシミュレーションからITF形式の操作列を生成する。Rustの照合テストは各操作を実装に渡し、返り値や状態を一手ずつ照合する。いずれかのモデルで照合が抜けてもコマンドは失敗する。

初回はnpmとGitHub Releasesから検査ツールを取得する。WindowsではRustの実行に `tools/cargo-windows.ps1` を使用する。MSYS2の配置先は `-MsysRoot` で指定できる。モデルだけを編集している間は `-ModelsOnly` でTLCとトレース生成を実行できる。CIはプルリクエストと `main` へのpushで全体を実行する。

## 検証する契約

| モデル | 対象と検証条件 |
| --- | --- |
| [capture](capture.qnt) | カメラの開始、切断、再接続、停止、リセット、スリープ。停止したカメラは復帰時も閉じたままにし、再接続は5回で打ち切る。Rustでは期限前・期限到達・試行枯渇の判定を照合し、ワーカーの開閉は模擬デバイスの既存テストで確認する。 |
| [slot](slot.qnt) | カメラ・推論間などで使う `LatestSlot`。2個の値を最大3回公開し、独立した2読者、消去、クローズを交互に実行する。読んだ値と世代、上書き数、閉鎖後の拒否を照合する。 |
| [face_worker](face_worker.qnt) | MediaPipeが顔なし、または変換エラーを返す場合の結果公開。顔なしは連続エラー数をリセットし、11回連続のエラーでワーカーが失敗する。閉じた出力への公開拒否も照合する。 |
| [inference](inference.qnt) | 検出器とランドマークを使う推論経路のROI。検出間隔を3、フレーム番号を0〜5とし、重複・逆行・スキップ、低信頼度、画面外のROIを含めて、再検出するフレームを照合する。 |
| [tracking](tracking.qnt) | 顔追跡の6状態。観測の有無と品質、信頼度シグナル、較正の有無、経過時間を組み合わせる。保持2・復帰3ティックで、タイムアウトと再捕捉が同時に起きる場合、超過時間の繰り越し、フィルターのリセットを検査する。 |
| [review](review.qnt) | UIから選んだVRMの利用条件の確認。選び直し・キャンセル・遅れて届いた読み込み結果で、別のファイルや未承認のファイルの取り込みが始まらないことを照合する。 |
| [avatar](avatar.qnt) | ロード、バインド、置換、失敗、アンロード。2個のルートと3世代で、連続置換中の最後の要求を保持し、同じルートを再利用しても古いバインドや制御フレームで新しいアバターを動かせないことを検査する。 |
| [arm_admission](arm_admission.qnt) | 上肢ソルバーが候補を採用する関節余裕と衝突距離の境界。それぞれ境界直下・一致・直上を組み合わせ、Rustの `Problem::feasible` に隣接する浮動小数点値を渡して判定を照合する。 |
| [arm_path](arm_path.qnt) | 採用済みの腕の経路を描画時刻で補間する処理。両向きの線形・イーズ補間で、端点の通過、逆行、オーバーシュートを検査する。8等分した時刻と5種類の端点座標で、整数による補間結果をRustの `JointPath::advance` と照合する。 |
| [readback](readback.qnt) | プレビューと外部出力が使う描画ターゲット。出力の再起動やスリープをまたいだGPUコールバックを拒否し、プレビュー単独で読み戻しを有効にしないことを検査する。未完了の要求1個について、出力と電源の世代を追跡する。 |
| [sender](sender.qnt) | NDI送信の開始中に届くフレーム、最新値への置換、停止と再開。テスト用バックエンドで起動完了の時点を制御し、コントローラーの応答と実際に送信されたフレーム番号を照合する。 |
| [camera_selection](camera_selection.qnt) | 2台のカメラの並べ替え・取り外し・再選択。選択を機器IDで追い、停止完了まで次の自動起動を待つこと、アバターの準備、カメラ障害後の再列挙と推論障害後の再試行を照合する。ワーカーの起動・停止通知はテストが渡す。 |
| [confidence](confidence.qnt) | 新しい推論結果だけを連続回数に数える。しきい値0.50と0.75の直下・一致・直上、非有限値、範囲外、保持フレーム、リセットを組み合わせる。獲得2回・低下3回・飽和3回の設定で、両カウンター、信頼状態、通知を照合する。 |
| [observation_age](observation_age.qnt) | 顔あり・顔なしと腕の観測を同じ時系列で再生する。セッション開始の直前・一致・直後に撮影したフレーム、250ミリ秒の有効期限の前後1ナノ秒、同じ連番の再利用を検査する。顔への新着通知と、遅れて届いた旧セッションの腕観測を捨てた後に保持するフレームを照合する。 |
| [hand_pose](hand_pose.qnt) | 開いた手と握った手の観測、判定が曖昧な握り、欠測を左右の手で再生する。同じ候補が4回、または確信度の高い候補が連続2回で確定することと、欠測時の出力・復帰後の候補を照合する。 |
| [calibration_samples](calibration_samples.qnt) | 手動較正が採用するフレームを、連番・同番・逆行、2種類の時刻、信頼度の下限と無効値で検査する。拒否した連番の再送、最後に採用した時刻との一致、5件で満杯になった後の拒否理由、リセットを照合する。 |
| [calibration_session](calibration_session.qnt) | 手動較正の開始、拒否、プロファイルの準備・確定、リセットを全順序で探索する。不正な要求が状態を書き換えず、選んだプロファイルだけが確定されることを照合する。 |
| [auto_neutral](auto_neutral.qnt) | 自動較正に2つの時刻で観測を渡す。15件の最低数、1.12秒の必要時間と1.2秒の保持期限の前後1ナノ秒、同時刻に集中した観測の38件上限を検査する。無効な観測や再センタリングの後もウィンドウと基準状態を照合する。 |
| [expression_keys](expression_keys.qnt) | 2キーと2表情で割り当て・移動・上書き・解除・初期化を探索し、キーから表情と表情からキーの両方向を照合する。 |
| [manual_expression](manual_expression.qnt) | アバター置換、古い世代からの切替・解除、同一更新内のキー入力2件をBevyに渡す。選択が1件に定まり、カタログが消えた場合や未知の表情を選んだ場合に、表情出力に渡せる選択が空になることを照合する。 |
| [preview_consent](preview_consent.qnt) | カメラ映像の表示要求・確認・非表示を、再描画や画面移動、カメラ選択、アバターの取り込み・解除、操作パネルの開閉と組み合わせる。同じ画面の再描画では同意を保持し、取り消し後は再度の要求と確認を必要とする。 |
| [video_frame](video_frame.qnt) | BGRA読み戻しの幅・高さ0〜2、行幅の不足・一致・パディング、バイト長の過不足、最大の行幅での積のオーバーフロー。エラーの種類と、成功時の画素の行順・バイト長・フレーム番号を照合する。 |
| [spout](spout.qnt) | WindowsのSpout送信待ちの1枠への上書き、破棄、アップロード中の停止。ネイティブ送信をテスト用コールバックに置き換え、送信した番号と停止後の状態を照合する。 |
| [syphon](syphon.qnt) | macOSのSyphon送信ループの受信側確認。確認中に次のフレーム、上書き、破棄、停止を挟む。切断の通知で待機フレームを捨て、停止後に遅れた接続通知が届いても配信を再開しないことを照合する。 |
| [bridge_discovery](bridge_discovery.qnt) | Looking Glassの機器探索中から、選んだ機器と別の機器の応答、不正な機器情報、ワーカー切断、停止、HLDへの変更を探索する。テスト用チャネルに応答を渡し、実際のBevyシステムが提示する機器と保存候補を照合する。 |
| [power](power.qnt) | スリープ・復帰の重複通知と、途中の通知を見逃す読み手。世代カウンターの周回直前から最大3回のスリープを行い、通知側・読み手側の世代とスリープ状態を照合する。 |

TLCの探索範囲は表の抽象化に従う。時刻・世代の上限には、タイムアウト、古い値、同一主体の再利用を区別できる値を選んでいる。Rustに再生するのはシナリオと固定シードで生成した操作列である。連続空間の骨長・関節軸・可動域、ノイズの増幅、最終的な骨の出力は追跡・アバターの回帰テストが扱う。実機のドライバー、GPU、フレームレートは各プラットフォームの動作確認で扱う。

## 機能を変更するとき

1. 変更が影響する契約を選び、追加した入力や状態を `step` から到達できるようにする。禁止したい結果を `safety` に、成立してほしい代表的な操作列を `run ...Test` に書く。新しい契約はこのディレクトリに同名のモジュールを持つ `.qnt` として追加する。
2. `quint_` で始まるRustの照合テストで、トレースのイベントを実装の入口に渡す。期待値はトレースから読み、実装の値は実行後に取得する。新しいクレートで照合するときは検証スクリプトのCargoパッケージ一覧にも加える。
3. 全体のコマンドを実行する。TLCの違反はログ中の `State 1` から順に読む。Rust側の不一致は失敗出力の `Replaying` が指すJSONに対象の操作列と期待値が残る。ローカルでは `target/quint/`、CIでは失敗した実行の `quint-traces` から確認できる。
