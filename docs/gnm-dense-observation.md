# GNM dense surface observation (Issue #53)

Status: implemented on `vtuber-gnm` (dense correspondence, dense observation,
dense 2D reprojection objective, deterministic rigid recovery evidence).

Scope of this document:

- how the repository-owned MediaPipe(478) → GNM Head v3 dense correspondence
  table was derived and validated,
- what is adopted and what is excluded, with counts,
- the runtime contracts that consume the table,
- the sparse-vs-dense conditioning evidence that justifies the dense data term.

Out of scope (later issues): identity/expression fitting (#54/#55/#64),
temporal smoothing, and ARKit-52 decode (#67).

**This is NOT an official Google correspondence table.** Google publishes a
68-point barycentric table for GNM (`head_sparse_68.txt`, already consumed by
the sparse bootstrap). The 470-row dense table below is derived and validated by
this repository; no row claims upstream MediaPipe↔GNM authority.

## Coordinate spaces

- **MediaPipe canonical OBJ space**: x− = subject right, y+, z+ forward;
  units span roughly ±8 over the cropped face.
- **GNM template space**: +X = subject **left** (established empirically: the
  `left_eye` joint sits at x ≈ +0.031 versus `right_eye` at x ≈ −0.031), y up
  (~0.065–0.407), z forward; face spans roughly 0.25 units.
- Both spaces share orientation semantics, so the canonical→template mapping is
  a similarity transform with rotation ≈ identity and scale ≈ 9.59e−3.

The runtime observation contract (`GnmDenseObservation::from_mediapipe_xy`)
accepts only normalized image `(x, y)` in `[0, 1]²` (x right, y down — the same
semantics as raw MediaPipe output). MediaPipe `z` is rejected **by type**: the
API has no z parameter, so tracker depth can never leak into geometry.

## Derivation method

One-time deterministic generator:

```text
cargo run -p vtuber-gnm --example derive_mediapipe_dense_mapping -- \
    <canonical_face_model.obj> [--out <table path>] [--diagnose]
```

Steps (all asserted in code):

1. Parse the pinned OBJ (asserts exactly 468 vertices) and load the real
   `gnm_head.npz` through `load_gnm_head_v3` (asserts version 3.0).
2. Materialize the neutral template surface **through the public evaluator**
   (`evaluate_sparse`); no private model access.
3. Verify anchor pairs against geometric assertions rather than trusting slot
   semantics: midline anchors must be near-zero-x in both spaces, side-carrying
   anchors must agree in sign outside documented dead zones (canonical ±0.5,
   template ±0.004).
4. Fit a similarity transform (Kabsch, uniform scale, Horn quaternion via
   cyclic Jacobi eigensolve) from verified central anchors to their dlib-68
   targets; refine after accepting secondary candidates whose residuals pass
   the central gate.
5. Snap every canonical vertex to its nearest template vertex; keep rows within
   `SNAP_TOLERANCE = 0.008`, enforce unique template targets and unique
   MediaPipe indices.
6. Derive barycentric iris-center targets (MediaPipe 468/473) at the midpoint of
   each fitted eye-corner pair via a least-squares barycentric solve over the
   six nearest vertices.

Anchor gates:

- Central tier: residual ≤ 0.010 template units.
- Contour tier (face oval): residual ≤ 0.025 — legitimate because the canonical
  crop lacks ears/scalp while the GNM template covers the whole head.

Measured quality (`--diagnose` on the pinned inputs; deterministic):

- Initial central-only fit: worst core residual 0.00861 (mp 197 → dlib 29),
  well under the 0.010 gate; refined fit on all 37 anchors reaches max
  residual 0.01630 (contour mp 454), scale 9.59e−3.
- Rejected secondary candidates, all eyelid mid points: mp 246→37 (0.01056),
  161→38 (0.01391), 7→40 (0.01544), 466→43 (0.01666), 249→47 (0.01545).
- Snap histogram (bucket width 0.002 template units): 348 points in
  [0, 0.002), 112 in [0.002, 0.004), 8 in [0.004, 0.006) — every adopted row
  within 0.006, zero distance-gate exclusions, zero side-mismatch exclusions,
  zero duplicate-target drops.
- Regeneration from the committed inputs is byte-identical to the committed
  table (same SHA-256).

## Runtime contracts (`vtuber-gnm`)

- `repository_dense_mapping()` — parsed once per process from the committed
  text schema (`mapping_version` header first, then `row` lines); any schema
  violation fails closed with the offending line context.
- `RepositoryDenseMapping::bind(&GnmModel)` → `DenseCorrespondenceSet` —
  validates model-version match (fail-closed on anything but 3.0), index
  bounds, duplicate sources/targets, finite positive weights.
- `DenseCorrespondenceSet::evaluate_surface(...)` — selected-surface evaluation
  reusing the model scratch; **no render mesh dependency**.
- `GnmDenseObservation::from_mediapipe_xy(...)` — retains only finite in-range
  `[0,1]²` points; coverage policy reports Valid/Degraded/Insufficient per
  frame; unmapped slots and invalid points are excluded, never interpolated.
- `DenseCorrespondenceSet::filter_rows(...)` — typed subsetting.
- `sparse_bootstrap_baseline(&GnmModel)` — materializes the official Google
  68-point barycentric table as a validated *reference* set over the identical
  model state: targets verbatim from `head_sparse_68`, iBUG-68 region layout,
  sides derived from pinned template geometry, uniform weights (the official
  table defines none). It deliberately fails primary-density validation; it is
  the Issue #81 comparison baseline, not an alternative observation path.
- `DenseRegionGroups::from_set(&DenseCorrespondenceSet)` — fail-closed typed
  partition of every row into exactly one region group (central face,
  contour, brows, eyelid rings, iris centers, mouth arcs, other) keyed by
  MediaPipe topology; a row whose stored `region` tag disagrees with its
  topology is rejected rather than reinterpreted.
- Evaluator/solver configuration (`DenseReprojectionConfig`,
  `RigidRecoveryConfig`) validates at construction and again at the public
  evaluation/recovery boundary: non-finite or out-of-range values fail closed
  instead of producing NaN weights or RMS values reported as successes.

## Dense 2D reprojection objective (`reprojection` module)

Conventions (documented on the type, enforced by tests):

- Camera space: `p_cam = Rz(roll) · Rx(pitch) · Ry(yaw) · p_head + t`.
- Image: `u = cx + f·X/Z`, `v = cy − f·Y/Z` (y down), principal point fixed.
- Residuals are Huber-weighted (`DenseReprojectionConfig::robust_delta`,
  default 0.02 normalized-image units) on top of static base weights:
  `w = base_weight · min(1, δ/‖r‖)`.
- Report carries per-point residuals, exclusion counts, and weighted RMS.

`recover_rigid_projection` estimates `[tx, ty, tz, yaw, pitch, roll, ln f]`
with a deterministic Levenberg-Marquardt loop (numeric central-difference
Jacobian, Huber IRLS, partial-pivot Gaussian elimination on the damped 7×7
normal equations). Identity/expression/joint state stays fixed during recovery
— this function is conditioning *evidence*, not the production fitter. The
surface is evaluated exactly once per call.

`compare_conditioning` runs several labeled baselines against one ground truth
and returns typed `ConditioningStats` (initial/final RMS, wrapped rotation
error, translation error, relative focal error, condition proxy).

## Sparse-vs-dense conditioning evidence

Machine-runnable proof lives in two layers:

- Unit tests (`crates/vtuber-gnm/src/reprojection.rs`): synthetic pseudo-3D
  models prove exact recovery, outlier rejection, behind-camera exclusion, and
  that the dense baseline retains more evidence than a sparse subset under
  identical noise.
- Integration tests (`crates/vtuber-gnm/tests/dense_mapping.rs`, real npz):
  the official Google 68-point barycentric table — materialized by
  `sparse_bootstrap_baseline` as a *reference* baseline over the identical
  synthetic state/projection (it never passes primary-density validation) —
  versus all 470 dense rows, driven through the Issue #81 synthetic-case
  suite: `neutral`, `yaw-pitch`, `mouth`, `eyelid`, coordinate noise across
  fixed seeds, partial invalidation, and bit-identical reruns.

The mouth/eyelid cases pick their deformation probe geometrically at plan time
(expression semantics are not decoded until Issue #67): `SyntheticCase::plan`
scans every expression coefficient and every single-joint axis rotation and
keeps whichever displaces the target region most specifically relative to the
rest of the face. On the pinned asset the mouth probe is expression
coefficient 201 (mean mouth-row displacement ≈ 3.3× the rest of the face) and
the eyelid probe is an eyeball-joint rotation (joint 2, axis 0; ≈ 27×
specificity with near-zero motion elsewhere — the expression basis contains no
strong isolated eyelid component).

Run the suite with:

```text
cargo test -p vtuber-gnm --test dense_mapping -- --nocapture
```

Measured results on the real model (deterministic; `rot_err` is the summed
absolute wrapped rotation error, `t_err` the translation error norm, `f_err`
the relative focal error):

Neutral case, zero noise: both baselines recover the ground truth exactly
(final RMS < 1e−6, zero wrapped rotation error); the conditioning proxy of the
recovered weighted normal equations is 1021.0 for dense-470 versus 471.5 for
sparse-68 — the dense objective is measurably better conditioned.

Noise case (yaw/pitch pose `[0.24, −0.18, 0.04]`, additive noise amplitude
0.002 normalized-image units):

| Seed | Baseline | Points | Final RMS | rot_err | t_err | f_err |
| --- | --- | --- | --- | --- | --- | --- |
| 7 | sparse-68 | 68 | 0.00086 | 0.0057 | 0.0024 | 0.0054 |
| 7 | dense-470 | 470 | 0.00095 | **0.0013** | 0.0053 | 0.0089 |
| 101 | sparse-68 | 68 | 0.00087 | 0.0015 | 0.0105 | −0.0174 |
| 101 | dense-470 | 470 | 0.00094 | 0.0025 | **0.0005** | 0.0010 |
| 2026 | sparse-68 | 68 | 0.00093 | 0.0057 | 0.0090 | −0.0161 |
| 2026 | dense-470 | 470 | 0.00095 | 0.0026 | **0.0041** | −0.0064 |

Both baselines improve the objective under every seed; dense-470 holds
rotation within 0.0026 on all seeds while sparse-68 degrades to 0.0057.
Focal length couples weakly with root depth for a mostly-frontal cloud, which
is why the tests assert bounded rather than tight per-seed focal accuracy.
Because inputs are deterministic, cross-seed fit variance is a hard number:
final-RMS variance 3.3e−11 (dense-470) versus 9.2e−10 (sparse-68). The printed
tables are diagnostic output, not a substitute for the assertions.

Mouth/eyelid cases pin region sensitivity through the public evaluator: the
mouth probe concentrates mean displacement ≈ 3.3× in Mouth rows (0.001212 vs
0.000367 template units) and the eyelid probe ≈ 27× in Eye rows (0.000483 vs
0.000018), each while pose recovery stays exact. The partial-invalidation case
drops every fifth mapped landmark deterministically: coverage accounting is
exact (sparse-68 retains 54 of 68 rows, dense-470 retains 376 of 470,
excluded-by-reprojection stays 0) and both baselines still converge from the
perturbed guess. Rerunning any case reproduces bit-identical statistics.

## Regenerating the table

The committed table is the source of truth; regeneration is a deliberate act
and uses only committed inputs. Regeneration writes the table (`--out`;
omitting it would overwrite the committed asset path directly):

```text
cargo run -p vtuber-gnm --example derive_mediapipe_dense_mapping -- \
    assets/models/canonical_face_model.obj \
    --out crates/vtuber-gnm/assets/mediapipe_dense_mapping_v1.txt
```

The diagnostic mode prints the measured quality report and exits **without
writing anything**:

```text
cargo run -p vtuber-gnm --example derive_mediapipe_dense_mapping -- \
    assets/models/canonical_face_model.obj --diagnose
```

A regeneration must reproduce `crates/vtuber-gnm/assets/mediapipe_dense_mapping_v1.txt`
byte-for-byte (same pinned npz and OBJ ⇒ SHA-256 `1706471a8093…83065`, the hash
of the committed git object as recorded in `assets/models/manifest.toml`;
re-verified for this commit. A Windows checkout with `core.autocrlf=true`
shows CRLF locally, so hash the git object — `git show HEAD:<path>` — rather
than the working-tree file). Any drift means inputs or gates changed
intentionally and `assets/models/manifest.toml` plus this document must be
updated together.
