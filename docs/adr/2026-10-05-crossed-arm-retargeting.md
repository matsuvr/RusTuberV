# 胸前の腕交差と掌回旋のリターゲット

状態: 採用。実カメラ録画を入力した Windows のアプリ表示で確認（2026-10-05）。

## 確認した問題

`data/video/WIN_20261004_22_48_07_Pro.mp4` の 9.5〜13.5 秒では、
演者は左右の前腕を胸前で重ね、手首を反対側まで運び、その位置で掌を回している。
変更前の Sapphy は両肘が外へ開き、手首が顔の中央付近で止まった。
AvatarSample_C は初期姿勢から腕が頭上へ上がり、同じ交差へ追従できなかった。
制約を満たすという solver status だけでは、映像との一致を確認できなかった。

切り分けでは、同じ入力・固定骨長・関節可動域のまま接触だけを外した求解で
胸前の交差へ到達した。一方、掌の目標だけを外しても元の接触判定では交差しなかった。
上腕と胸の剛体カプセルが肩の接続部分で重なることを、腕全体の貫通と同様に
拒否していたのが主因だった。接触を外した診断用コードは残さない。

## 肩の接続部分

- 読み込み時の skin 適合で、上腕と胴の両方に正の weight を持つ頂点を集める。
  肩関節中心からの最大距離を、そのモデルの肩接続範囲の半径とする。
  既存の体形 morph、inverse bind、骨の rest 座標を使い、実行中に頂点を再計算しない。
- この共有領域のうち上腕が主 weight の頂点を、剛体上腕カプセルへ重複して含めない。
  胴と上腕の間で変形する肩の skin を上腕だけに固定すると、胸前へ寄せた際の
  占有領域を過大に見積もるため。胴側のカプセルと肩接続範囲は残す。
- 対象は同じ上腕と胴の組だけ。二つのカプセルが離れているか、重なり全体が
  肩中心のこの範囲内に収まる場合に限り許容する。前腕・手・反対腕は除外しない。
- 重なりの外包には、肩中心を原点とした各カプセルの AABB の共通部分を使う。
  共通部分の最遠角までの距離は、カプセルの重なり全体の距離の上界になる。
  最深接触点一つだけで判定せず、肩から離れた別の接触も範囲内か確認する。
- 連続経路でも、始点・終点それぞれの肩中心を引いた swept capsule を使う。
  既存の FK 曲線の弦誤差に肩中心の移動の上界を加え、同じ範囲内か確認する。
  両端だけが安全でも、途中で胴を横切る経路は受理しない。

これは skin の接続を持つ剛体近似であり、骨長や人体の可動域の緩和ではない。
[MuJoCo の自己衝突除外](https://mujoco.readthedocs.io/en/stable/computation/index.html#collision-detection)
にある接続された body を区別する考え方を参照するが、上腕と胸の組全体を除外せず、
モデルの接続領域に限定する。AABB の包含判定は本実装の保守的な幾何近似であり、
MuJoCo に同じアルゴリズムがあるという意味ではない。
以前の全 skin 凸包・交差多面体・面クリップは復活させない。

接続半径はモデルの skin weight に依存し、カプセルも衣服を含む近似である。
極端な weight や形状を含む全 VRM の非貫通保証とはしない。今回の bind では
Sapphy が左右約 0.150 m、AvatarSample_C が左右約 0.203 m だった。

## 掌の評価を位置と同じ尺度にする

以前の目的関数は、腕長で正規化した肘・手首の位置誤差と、掌法線・長軸の
単位ベクトルの誤差を同じ尺度で加算していた。掌の回転を腕長相当の変位として
扱うため、掌を回すと肘・手首を動かして誤差を下げる傾向が強かった。

掌フレームで、モデルの手首から人差し指・小指 MCP への実寸ベクトルを回す。
その二つのマーカーの距離誤差を肘・手首と同様に腕長で割り、既存の観測信頼度で
重み付けする。手首からの相対位置なので手首位置の誤差を二重に足さない。
掌の評価用の独自係数は追加しない。

根拠は [OpenSim の重み付きマーカー最小二乗による IK](https://opensimconfluence.atlassian.net/wiki/spaces/OpenSim/pages/53090047/How+Inverse+Kinematics+Works)。
本実装では観測された掌フレームと VRM の実寸から目標マーカーを作り、
OpenSim のマーカー計測やソルバーそのものを導入するものではない。
前腕回旋・手首の自由度、制約、減衰状態、FK の一度だけの継承は維持する。
求解後に観測回転を重ねる補正は追加しない。

## 肘位置を保持する

追跡側の `stabilize_elbow_pole` は、旧 two-bone IK の bend plane 用に
肩―手首軸に垂直な成分だけを返していた。現在の制約ソルバーは同じ値を
肘の位置目標として使うため、軸方向の成分を失うと別の肘位置を要求してしまう。
観測肘を軸方向と垂直方向に分け、既存の安定化を垂直方向に適用した後で
軸方向を戻す。描画 tick 間の spring と bend plane の速度制限は維持する。

## 見えている前腕の奥行き

15.5〜16.5 秒の逆向き交差では、生の Pose world 座標が、映像で胸前に見えている
肘・手首を肩より奥へ置くことがあった。モデルを Full から Heavy へ変更するだけでは
解消しなかったため、採用済みの Full を維持する。

両端の観測が採用されている前腕は、対象アバターの胴のカメラ側に置ける目標へ
リターゲットする。既存の skin 適合で得た前腕半径と胴カプセルを使い、肘―手首の
カプセルを、確実に胴の手前となる支持面から元の目標までカメラ軸方向に shape cast
する。最初の接触位置までの共通平行移動を両端へ加える。遮られない目標は動かさない。
画面平面内の座標と肘―手首間の相対ベクトルを保持し、固定の奥行きや Z の符号反転は
使わない。点を個別に投影するだけでは、両端の間が胴を横切るため、前腕全体を扱う。

これは単眼推定の正確な三次元位置を復元する処理ではなく、可視の前腕を対象形状へ
移すための幾何制約である。形状と接触を考慮して動作を移す考え方は
[Contact-Aware Retargeting of Skinned Motion](https://arxiv.org/abs/2109.07431)
を参照する。論文の学習ネットワークを実装したものではない。幾何演算は既存依存の
Parry の capsule support-map shape cast を使う。

この変換は観測目標に対して一度だけ行い、その後の既存ソルバーが固定骨長、関節可動域、
両腕・胴との接触を守って FK を求める。最終姿勢に位置・回転を上書きしない。

## 接触付近の収束判定

line search が接触回避のため短縮したステップの小ささを、収束と取り違えない。
数値停止は短縮前の QP 提案で判定する。ライブ更新は従来どおり採用した局所ステップを
一つずつ表示経路へ渡す。複数ステップの終点をまとめて渡す案は、中間で接触する経路を
作って停止・遅延を増やしたため採用しない。連続経路判定・可動域は緩和しない。

胴や指が動いて接触の数値的な内側への復元が必要な場合、その復元を観測追従の
一ステップとして消費しない。以前は片腕の微小な接触修正だけで毎回の更新を終え、
反対腕が開いた姿勢のまま再交差に追従しなかった。既存の中立姿勢と同じ最大 96 回の
数値反復内で復元してから、一つの追従ステップを求める。関節・接触の境界は変更せず、
合成した始点から終点への経路は従来どおり連続判定する。

既存の第二初期値も、局所解が少し動いている間に継続して求解する。接触によって
上下関係の異なる解に留まる場合でも、より誤差の小さい解を探索できるようにする。
進行中の局所ステップと比較するのは、第二候補の遠い終点ではなく、そこへ向かう
連続経路が通る局所ステップの誤差とする。既存 SQP の最大ステップと同じ角度まで
補間し、既存経路探索と同じ二分の backtracking で、関節・接触条件を満たす部分を
求める。その部分でも誤差が小さくなる場合だけ採用し、遠い候補自体は次回の求解へ保持する。
これにより、途中まで安全に進める候補を終点への接触だけで捨てず、遠い姿勢を一括採用して
長い再生待ちを作ることも避ける。初期値や探索経路の種類、人体の制約は追加しない。

## 急変除外の後に観測を再採用する

最適化版の短い再交差では、片腕の目標位置が交差前の位置に留まり、後から観測重みが
下がっていた。`max_wrist_step` は一観測間の変位上限なのに、除外した観測を記録せず
最後に採用した目標と比較し続けていた。その位置から離れた正常な観測も除外される。

前回の有効な観測手首を採否とは別に保持し、変位を観測同士で比較する。最初の急変は
従来どおり採用しない。続く観測が安定すれば既存の spring・blend を通して追従を再開し、
大きく飛び続ける観測は除外して中立姿勢へ戻る。位置を直接上書きせず、変位上限、
visibility と手検出の条件、実際の欠測からの復帰条件、減衰の時定数は変更しない。
以前の実装で安定した新位置が採用されない回帰テストが失敗し、修正後に通ることを確認した。

## 確認範囲

最適化版で短い再交差を落とす走行が残ったため、急変除外からの観測再採用と、
第二候補の到達可能な途中姿勢の比較を追加した。以下は両方を含む最終 release の確認結果。
Sapphy は再起動して二回、AvatarSample_C は一回再生し、短い再交差と開腕を確認した。

実 MediaPipe の Pose/Hand、既存の desktop plugin、描画を使う `xtask tracking-replay`
で同じ録画を再生し、Sapphy（VRM 0.x）と AvatarSample_C（VRM 1.0）の表示を目視した。
アプリ既定の動作ミラーを考慮して元映像を左右反転して比較した。

- 9.5〜13.5 秒: 両モデルで前腕を胸前に重ね、左右の手首を反対側へ運ぶ。
  掌を回しても交差を保ち、腕全体が頭上へ逃げない。
- 15.5〜16.5 秒: 上下関係を入れ替えて交差し、17 秒以降に再び開く。
- 18.5〜19.2 秒: 短い再交差にも追従する。Sapphy は手首が反対側へ達するのが
  AvatarSample_C より遅く、交差の深さも浅いが、開いた姿勢で停止して動作を丸ごと落とす
  問題は最終の二走行では再発しなかった。
  20 秒には両モデルで交差を解いて開腕する。
- 終盤: 腕を下ろす。通常動作の `WIN_20261004_22_29_52_Pro.mp4` も Sapphy で再生し、
  挙手、掌・指の動作をプレビューと保存 PNG で目視した。

実行中のプレビューと保存された描画 PNG の両方を確認した。比較画像はローカルの
`data/video/arm-review-20261005/release-crossing-comparison.jpg`。
同ディレクトリ内の最終 release 記録は `accepted-release-sapphy/`、
`accepted-release-sapphy-repeat/`、`accepted-release-sample/`、`accepted-release-normal/`。
交差再生の表示中の腕入力の年齢 p95 / 最大は、Sapphy が約 102 / 168 ms、
その再実行が約 118 / 201 ms、AvatarSample_C が約 102 / 119 ms。
通常動作は約 102 / 185 ms。いずれも表示は約 60 fps だった。
この値は表示中の腕姿勢が参照する録画フレームの予定撮像時刻からの経過時間であり、
センサー・NDI・GPU の提示完了までを含む遅延ではない。

モデル間の骨長比率・肩幅・袖の厚みの差は残る。手首の高さ・肘の位置の完全な一致や、
単眼映像からの正確な三次元位置の復元は主張しない。Sapphy の上側の袖は顔にかかる。
固定骨長、採用済みの関節自由度・可動域、描画 tick 間の減衰は維持している。
