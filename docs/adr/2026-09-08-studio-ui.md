# Studio UI, camera consent, and clean avatar output

Date: 2026-09-08

## Decision

Windows and macOS share an Apple-style light desktop workspace implemented in Rust/egui. This is an information-architecture and interaction choice, not a SwiftUI port. No virtual-camera driver, virtual-camera option, or new dependency is added.

The sidebar contains destinations only: Studio, Avatar, Camera, Calibration, Output, Settings, and Diagnostics. Session commands and status are in the toolbar. Controls are in the selected page. Studio guides the user through importing a VRM, selecting a camera, starting tracking, and checking output. Existing backend functions are reused; mock-only exposure controls or other nonfunctional controls are not added.

The avatar monitor stays outside the settings scroll area. At smaller window widths it moves above the settings and navigation becomes a destination picker. F1 returns to the existing large avatar viewport and reopens settings. Camera interaction belongs to the large avatar viewport; settings-panel pointer input must not move the avatar camera.

## Rendering boundary

The monitor samples `AvatarOutputTarget.image()`, the same avatar-only texture read back for NDI. Its frame, labels, settings, errors, and the camera preview are drawn by egui on the main window camera, never into that texture. `PrimaryEguiContext` attaches explicitly to `AvatarViewportCamera`, not `AvatarOutputCamera`.

`AvatarOutputState::set_preview_visible(bool)` requests GPU rendering only. The existing `activate`/`deactivate` state controls transport readback independently. A visible monitor must keep rendering when NDI stops, and an NDI sender must keep rendering when settings close. Merely viewing the monitor must not start NDI or CPU readback.

## Camera privacy contract

`next_camera_preview_consent(current, event)` is a pure, session-only transition:

- Hidden + Request -> Confirming.
- Confirming + Confirm -> Visible.
- Any state + Hide -> Hidden.

Opening any page is not consent. Navigation, a changed camera selection, stopping tracking, unloading the avatar, closing/reopening settings, and Escape revoke preview consent. The application initializes the preview as hidden. Consent is never persisted. The Hide action suppresses image drawing in the same UI pass. The existing low-resolution camera texture conversion remains unchanged.

The confirmation text explicitly warns that desktop/window capture can broadcast the camera preview and surroundings. NDI remains avatar-only even when the operator intentionally reveals the camera. The application cannot hide a visible settings window from another application's desktop/window capture, and the UI must not claim otherwise.

## Language

Japanese is the initial language, regardless of the OS locale. English, Simplified Chinese (`zh-Hans`, accepting `zh` on input), and Korean are available in Settings. The existing `settings.toml` persists the choice; documents without a language retain the Japanese default. `UiLanguage::pick(ja, en, zh, ko)` requires all four translations at every call. Technical identifiers and raw backend details are explicitly labeled as original text.

Japanese/English retain the already-bundled LINE Seed JP font. Chinese/Korean read the local Windows or macOS system font at language change; system fonts are not copied into the repository or distribution. Failed font loading is reported explicitly with Japanese/English selection buttons, not a silent language substitution. Native file-dialog titles/filters use the selected language; OS-owned dialog buttons follow the OS.

## Verification

Unit tests cover consent transitions/revocation, locale selection and persistence, initial-language compatibility, render/readback independence, and exclusion of the output camera from egui attachment.

Local merge validation covers formatting, workspace tests and Clippy, and the NDI/synthetic-input feature builds. Camera reset still restores the saved auto-framed pose and recenters tracking; auto-framing still unions all identified hair meshes beneath the avatar root. The refreshed Avatar page exposes the existing reset action.

Windows/macOS visual acceptance remains a separate, pending check. In particular verify:

1. Japanese startup and all four languages after restart, including Chinese/Korean glyphs and system-font file paths.
2. First navigation to Camera never emits camera pixels; Cancel, Escape, navigation, close/reopen and camera changes return to hidden.
3. Avatar preview remains live while scrolling every settings page and after stopping NDI.
4. NDI receiver sees only the avatar during all menu operations, including a deliberately revealed webcam preview. Check alpha and the unchanged framing.
5. Wide and narrow windows, F1, mouse camera controls, VRM import/replacement/unload, calibration, and tracking start/stop.

The initial PR authoring environment had no Rust toolchain. Local verification results are recorded in the PR; automated tests do not establish GPU, webcam, NDI receiver, or macOS visual acceptance.
